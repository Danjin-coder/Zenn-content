Google Julesは、AI支援によるソフトウェア開発を一歩前に進める、興味深い存在でした。作業中にコードを提案するだけでなく、割り当てられたタスクを引き受け、GitHubリポジトリを調べ、計画を立て、ファイルを修正し、テストを実行して、レビューできる変更を用意できたのです。

この非同期の仕組みは、AIコーディングアシスタントを常に見守らずに、作業を任せたい開発者にとって便利でした。


![画像の説明](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/7josteta3u9z1p999o82.png)




ただし、利用を始める前に知っておくべき重要な更新情報があります。

**Googleは2026年10月29日、Julesを2026年12月31日に終了すると発表しました。2026年11月11日からは、サービスは読み取り専用になります。** 既存のコード、ブランチ、プルリクエストはGitHubに残りますが、サービス終了までにJulesのデータをエクスポートしておく必要があります。

そこで、Julesを試してみたいと思っていた方に向けて、この記事では仕組みや、利用可能な間の使い方、今後検討すべきことを説明します。

## Google Julesとは？

![画像の説明](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/uycy84sjn1az39636glw.png)


[Jules](https://jules.google/)は、Googleの非同期AIコーディングエージェントです。GitHubリポジトリに接続し、分離されたクラウド環境でソフトウェア開発タスクを実行します。

従来のコード補完アシスタントとは異なり、Julesはタスクを最初から最後まで扱うように設計されています。

たとえば、次のような作業を依頼できます。

- 既存アプリケーションのバグを修正する。
- 特定の関数にユニットテストを追加する。
- 古くなった依存関係を更新する。
- 小規模な機能を実装する。
- コードの一部をリファクタリングする。
- プロジェクトのドキュメントを改善する。

JulesはGoogleのGeminiモデルを使い、タスクを理解してリポジトリを扱います。クラウドの仮想マシンに開発環境を作り、プロジェクトを調べ、レビュー可能な変更を生成します。

基本的なワークフローは次のとおりです。

1. GitHubリポジトリを接続する。
2. 開発タスクを説明する。
3. Julesが生成した計画を確認する。
4. タスクの実行を許可する。
5. 変更内容とテスト結果を確認する。
6. ブランチを作成し、プルリクエストを開く。

重要なのは、Julesが非同期で動くことです。タスクを送信したら、実装を任せている間、自分は別の作業を進められます。

## Julesを使う前に用意するもの


![画像の説明](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/5ncqtxvxzmjqfyk53hv2.png)



始める前に、次のものを用意してください。

- Googleアカウント。
- GitHubアカウント。
- Julesに作業してもらいたいプロジェクトのリポジトリ。
- Julesによるそのリポジトリへのアクセスを許可する権限。

リポジトリが、ある程度正常な状態にあることも確認しておきましょう。依存関係が不足していたり、手順が不明確だったり、テストが失敗していたりすると、エージェントが加えた変更の品質を評価しにくくなります。

Googleのドキュメントでは、コーディングエージェントにリポジトリ固有の指示を伝えるため、`AGENTS.md`ファイルの利用も推奨されています。

たとえば、このファイルに次の内容を記載できます。

- プロジェクトのアーキテクチャ。
- 使用しているフレームワークとライブラリ。
- 依存関係のインストール方法。
- テストの実行方法。
- コーディング規約。
- アプリケーションを変更する際の重要な制約。

これにより、プロジェクトがどのように動作すべきかについて、Julesに追加の文脈を渡せます。

## ステップ1：Google Julesを開き、GitHubを接続する

まず[jules.google](https://jules.google/)にアクセスします。

Googleアカウントでログインし、初期設定の手順に従ってください。

次に、GitHubアカウントを接続します。

Julesは個々のファイルを手作業でアップロードしてもらうのではなく、既存のコードを直接扱うため、リポジトリへのアクセス権が必要です。

認可の際には、Julesにアクセスを許可するリポジトリを選べます。

最初からすべてにアクセスを許可するより、特定のリポジトリから始めることをおすすめします。エージェントが扱えるプロジェクトを、より適切に管理できるからです。

GitHubの接続が完了したら、Julesに戻ります。

これで、アクセスを許可したリポジトリと、使用するブランチを選べるようになります。

## ステップ2：リポジトリとブランチを選ぶ

Julesに変更してもらうコードがあるリポジトリを選択します。

次に、作業の起点にするブランチを選びます。

例：

- リポジトリ：`my-project`
- ブランチ：`main`

Julesは、選択したブランチを起点として作業します。

実際に本番運用しているプロジェクトでは、メインブランチを未レビューの変更を置く場所として扱うのは避けたいところです。開発用ブランチなど、適切な起点を使い、マージ前に変更をレビューしてください。

こうすることで、エージェントの作業を既存の実装と比較しやすくなり、必要に応じて変更を元に戻しやすくなります。

## ステップ3：具体的なコーディングタスクをJulesに伝える


![画像の説明](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/p90ylx0fpw4zvduxyt6y.png)



ここでは、指示の質が重要になります。

たとえば、

「アプリケーションを改善して」

という曖昧なプロンプトでは、Julesに十分な方向性を示せません。

大まかな意図は理解できても、アプリケーションのどこに手を入れるべきか、どのような結果なら成功といえるかは、推測する必要があります。

代わりに、問題、期待する動作、関連する制約を説明してください。

たとえば、次のタスクを見てみましょう。

**プロンプトの例：**

```plaintext
Add unit tests for the parseQueryString function in utils.js.

Requirements:
- Cover empty query strings.
- Test multiple query parameters.
- Test URL-encoded values.
- Test parameters without values.
- Follow the existing testing conventions in the repository.
- Do not modify the function's implementation unless a bug prevents the tests from passing.

Run the relevant test suite and report the results.
```

作業範囲と測定可能な期待値が明確なので、Julesにとってはるかに役立つ指示です。

別の例もあります。

```plaintext
Investigate the login form validation in the application.

The form currently accepts an invalid email address.

Please:
1. Locate the existing validation logic.
2. Explain the cause of the problem.
3. Propose a minimal fix.
4. Add tests covering valid and invalid email addresses.
5. Avoid changing unrelated authentication functionality.
```

二つ目の例では、変更する前に調査することも求めています。問題がどこで起きているか、まだはっきりしていない場合に有効です。

## ステップ4：実行前に計画を確認する

![画像の説明](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/qsi0ubgw5toizz2al5ut.png)



プロンプトを送信すると、Julesはタスクへの取り組み方を説明する計画を生成します。

どの計画も無条件に承認するのは避けてください。

要件を理解しているか、提案された変更が作業範囲に収まっているかを、少し時間を取って確認しましょう。

たとえば、テストの追加を頼んだのに、計画に認証システムの再構築が含まれているなら、いったん止めてタスクを明確にする必要があります。

役立つ計画には、次の内容が説明されているはずです。

- 変更する予定のファイル。
- 加える予定の変更。
- 実装の検証方法。
- 依存関係の追加や設定変更が必要かどうか。

不明な点があれば、計画を承認する前にフィードバックしてください。

大量のコード変更をすぐに受け入れるのではなく、提案された進め方を先に確認できるのは、Julesのワークフローの便利な点の一つです。

## ステップ5：Julesにタスクを実行してもらう

計画を承認すると、Julesはクラウド環境で作業を開始します。

リポジトリをクローンし、開発環境を準備して、必要な変更を加えます。

タスクによっては、コマンドの実行、依存関係のインストール、テストの実行も行えます。

作業中ずっとJulesの画面を開いておく必要はありません。通知を有効にすれば、タスクが完了したときや、対応が必要になったときに更新を受け取れます。

タスクの実行中にも、フィードバックを送れます。

たとえば、次のように伝えられます。

```plaintext
The current implementation changes more files than necessary.

Please keep the solution focused on the login validation issue
and avoid modifying the shared authentication service.
```

エージェントの進む方向を修正できることは重要です。自律的に実行するからといって、開発プロセスの主導権を手放す必要はありません。

## ステップ6：変更をレビューし、プルリクエストを作成する

Julesが作業を終えると、作業内容の要約が表示されます。

変更したファイル、差分、実行結果を確認できます。

特に、次の点に注意してください。

- 変更が元の問題を実際に解決しているか。
- 関係のない機能を変更していないか。
- テストが成功しているか。
- 新しい依存関係を追加していないか。
- プロジェクトの規約に沿った実装になっているか。

変更を受け入れられると判断したら、ブランチを作成し、それを使ってGitHub上でプルリクエストを開けます。

プルリクエストなら、使い慣れた場所でコードをレビューし、追加の修正を求め、マージできる状態かを判断できます。

**Julesのタスクが完了したことを、そのままマージの承認と捉えないでください。** テストが成功していても、ロジックの誤り、セキュリティ上の問題、予期しない動作が残っている可能性があります。

人によるレビューは引き続き不可欠です。

## ステップ7：GitHub Issuesからタスクを開始してみる


![画像の説明](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/76lldz11mgde95eueh37.png)



Julesの便利な機能の一つが、GitHub Issuesとの連携です。

毎回Julesを開いてタスクを手入力する代わりに、GitHubのIssueから作業を割り当てられます。

対応するリポジトリでは、Issueに`jules`ラベルを追加します。するとJulesがタスクを引き受けて作業し、作成したプルリクエストへのリンクを返せます。

たとえば、次のようなGitHub Issueを用意できます。

**タイトル：** 商品APIにページネーションを追加する

**説明：**

```plaintext
The product endpoint currently returns every product
in a single response.

Implement pagination using the existing API conventions.

Requirements:
- Support page and limit parameters.
- Return pagination metadata.
- Preserve existing response compatibility.
- Add tests for pagination behavior.
```

必要なリポジトリへのアクセスが許可されていれば、`jules`ラベルを追加した後、エージェントはそのIssueの作業を開始できます。

すでにGitHub Issuesで開発バックログを管理しているチームには、特に便利です。

## Julesにはどのような制約がある？


![画像の説明](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/5xw8tfgofuttmy852gli.png)



サービス終了の発表前から、Julesには開発者が理解しておくべき制約がありました。

**1. 適切な指示は依然として必要**

自律型のコーディングエージェントでも、アーキテクチャ上の判断や業務要件をすべて確実に推測できるわけではありません。タスクの定義が不十分だと、技術的には動いても、意図した解決策とは異なる変更が生まれる可能性があります。

**2. 生成されたコードにもレビューが必要**

テストの成功は役立つ情報ですが、変更が正しく、安全で、本番投入できる状態であることの証明にはなりません。

**3. リポジトリへのアクセスは慎重に管理する必要がある**

Julesは、リポジトリ内で利用できるコードやファイルを扱います。外部のコーディングエージェントに接続するリポジトリには、シークレット、認証情報、機密情報をコミットしないようにしてください。

**4. 利用上限がある**

Julesは、無料枠や、Google AIのサブスクリプションによる上限の拡大など、複数の利用区分を提供してきました。上限や利用条件は変わる可能性があるため、古い料金記事に頼らず、[公式の利用上限ドキュメント](https://jules.google/docs/usage-limits/)を確認してください。

**5. サービスの終了が予定されている**

現在、これが最大の制約です。Googleは、Julesを2026年11月11日に読み取り専用にし、2026年12月31日に終了すると発表しています。

そのため、Julesだけに依存する長期的なワークフローの構築は避けるべきです。

## 重要：サービス終了前にJulesのデータをエクスポートする方法


![画像の説明](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/vvs7r9v3fup6zsuuoo8a.png)



Googleの10月29日の発表によると、ユーザーはJulesのデータをローカルフォルダーにエクスポートできます。

エクスポートには次の情報が含まれます。

- アカウント設定。
- 環境変数。
- スケジュールされたタスク。
- 接続したリポジトリ。
- メモリ。
- セットアップスクリプト。
- セッションのプロンプトと計画。
- アクティビティログ。
- コードのパッチ。

すでにGitHubに保存されているコード、ブランチ、プルリクエストは、そのまま残ります。ただし、過去の作業の背景も保存できるよう、Jules固有の情報もエクスポートしておくとよいでしょう。

私なら、Julesが読み取り専用になる予定の11月11日より前に、この作業を優先します。

最新の手順は、[Julesの公式更新履歴](https://jules.google/docs/changelog/)を確認してください。

## Google Julesの代替ツールは？

サービスの終了によって、開発者は次に何を使うべきかという現実的な問題に直面します。

個人で使うコーディングエージェントが欲しいのか、それとも開発ワークフロー全体で複数のエージェントを調整したいのかによって、検討すべき方法はいくつかあります。

### Sharkly — 複数のAIコーディングエージェントを調整するなら


![画像の説明](https://dev-to-uploads.s3.us-east-2.amazonaws.com/uploads/articles/mrq26v06va2i8phnj0jw.png)



検討する価値のある選択肢の一つが[Sharkly](https://sharkly.ai/)です。

Julesがコーディングタスクの非同期実行に重点を置くのに対し、Sharklyは、より広いタスク管理と作業調整の視点から取り組みます。

開発タスク、バックログ、スプリント、AIエージェントの実行を、共通のワークフローにまとめます。

たとえば、開発チームには次のような複数の課題があるかもしれません。

- 認証モジュールのバグを修正する。
- 決済サービスにテストを追加する。
- APIドキュメントを更新する。
- コンポーネントをリファクタリングする。
- 性能の問題を調査する。

コーディングエージェントを一つずつ個別に管理する代わりに、チームでタスクを整理し、適した作業を対応するエージェントに割り当てられます。

Sharklyは、Claude Code、Codex、Gemini CLI、OpenCodeなどのコーディングツールに対応しています。

主な便利な機能には、次のものがあります。

- AIエージェントへの開発タスクの割り当て。
- 別々のタスクを処理する複数のエージェントの調整。
- タスクの文脈と実行結果の一元管理。
- 分離されたworktreeを使ったコーディング作業の並列実行。
- 共通のタスク管理ワークフローを通じた進捗の追跡。

一つのコーディングエージェントを試す段階を超え、エージェントによる開発をより体系的に管理したいチームに、特に役立ちます。

役割の違いを理解することが大切です。Sharklyは、Julesのクラウド環境や、まったく同じワークフローを直接置き換えるものではありません。対応するエージェントを使い、開発作業を整理・調整する別の方法を提供します。

詳しくは[Sharkly.ai](https://sharkly.ai/)をご覧ください。

### ほかにも検討したい選択肢

| ツール | 提供する機能 | 特に向いている人・チーム |
| --- | --- | --- |
| [Claude Code](https://docs.anthropic.com/en/docs/claude-code/overview) | ターミナルのワークフローで使うエージェント型コーディング | コードベースを直接扱うエージェントが欲しい開発者 |
| [OpenAI Codex](https://openai.com/codex/) | クラウドでのコーディングタスクとエージェントによる開発支援 | コーディングタスクを任せたい開発者 |
| [Gemini CLI](https://github.com/google-gemini/gemini-cli) | ターミナルで動くオープンソースのAIエージェント | コマンドラインでの作業を好む開発者 |
| [Sharkly](https://sharkly.ai/) | 対応する複数のコーディングエージェントのタスク管理と作業調整 | 複数のエージェントと開発タスクを管理するチーム |

適切な選択肢は、仕事の進め方によって変わります。個人で使うコーディングエージェントが欲しいなら、Claude Code、Codex、Gemini CLIなどを調べてみるとよいでしょう。複数のエージェントを調整し、共通のバックログと作業を結び付けたいなら、Sharklyが別のレイヤーで作業の整理を支援します。

## おわりに

Google Julesは、AI支援によるソフトウェア開発の興味深い方向性を示しました。開発者は、実質的な開発タスクを任せ、提案された計画をレビューし、後から戻って実装を確認できたのです。

非同期のワークフローが便利だったのは、個別のコード提案を生成することから、より大きく、明確に定義されたタスクを完了することへ、焦点を移したからです。

ただし、Googleが2026年末までにJulesを終了する方針となった今、開発者は、長期的なJulesワークフローの始まりではなく、移行の節目として捉えるべきでしょう。

すでにJulesを使っているなら、データをエクスポートし、重要な作業を保存してください。代替手段を探しているなら、コーディングタスクをどう管理し、変更をどう実行し、結果をどうレビューしたいかに基づいて、ツールを評価しましょう。

そして、チームで複数のAIコーディングエージェントを使い始めているなら、個々のエージェントだけでなく、開発ワークフロー全体の中にどう組み込むかを考える時期かもしれません。

## よくある質問

### Google Julesは無料で使えますか？

Julesは、無料の利用枠に加え、対象となるGoogle AIサブスクリプションで、より高い利用上限を提供してきました。利用可能な上限やプランは変わる可能性があります。公式の[Jules利用上限ページ](https://jules.google/docs/usage-limits/)を確認してください。

### Google JulesはGitHubと連携できますか？

はい。Julesは、アクセスを許可されたGitHubリポジトリに接続し、選択したブランチを起点に作業して、変更を含むブランチやプルリクエストを作成できます。

### Google Julesはコードを書いてテストできますか？

はい。Julesはクラウド環境でコードを修正し、依存関係をインストールし、コマンドや既存のテストを実行できます。ただし、マージ前には開発者が変更をレビューする必要があります。

### Google Julesは終了するのですか？

はい。Googleは2026年10月29日、Julesを2026年12月31日に終了すると発表しました。2026年11月11日からは読み取り専用になる予定です。

### Google Julesの代替として最適なのはどのツールですか？

Julesのすべてのワークフローを一つで置き換えるツールはありません。Claude Code、OpenAI Codex、Gemini CLIは、エージェント型のコーディング機能を提供します。複数のコーディングエージェントを調整し、開発タスク全体で作業を整理することが課題なら、Sharklyも検討に値します。

### サービス終了後もJulesのプロジェクトにアクセスできますか？

Googleによると、すでにGitHubに保存されているコード、ブランチ、プルリクエストは、そのまま残ります。Jules固有の情報は、サービスが読み取り専用になる前にエクスポートできます。最新の手順は、公式の[Jules更新履歴](https://jules.google/docs/changelog/)を確認してください。
